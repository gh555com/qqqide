**前端开发者新建 HTML 模板必须遵守的规则**：

必须做的 4 件事：
```
① <head> 中引入两个脚本（顺序不能反）：
   <script src="/static/i18n.js"></script>
   <script src="/static/swww.js"></script>

② 所有用户可见文本用 data-i18n 属性：
   短标签（<10字）保留中文回退：<span data-i18n="pages.xxx.title">标题</span>
   长段落（≥10字）留空：<span data-i18n="pages.xxx.intro"></span>
   <input data-i18n-placeholder="common.search" placeholder="搜索">

③ 只在 zh.json 中添加对应的中文 key-value（唯一真理源）
   其他 12 种语言会被 ky.py 一键 deploy 时自动差异翻译

④ JS 中需要翻译的字符串用 _q()：
   const msg = _q('common.success', '成功');
```

不要做的 3 件事：
```
✗ 不要直接修改 en/ja/ko 等其他语言的 JSON 文件
✗ 不要在 HTML 里硬编码任何用户可见的中文/英文
✗ 不要忘记 i18n.js 必须在 swww.js 之前加载
```

**运维脚本联动更新规范（AI 必须遵守）**：

两个关键运维文件：
```
cf/ky.py          — 部署脚本（编译/同步/迁移/翻译/备份/回滚/清缓存/对账）
cf/provision.sh   — 服务器初始化脚本（OS/PG/Redis/Go/Nginx/systemd/.env模板/时间同步）
```

触发规则（代码改完后必须检查）：
```
🔴 新增/删除/重命名 .env 变量       → 同步 provision.sh 的 .env 模板 + ky.py 的 SYNC_ENV_KEYS
🔴 新增/删除 migrations 文件         → ky.py 的 RUN_MIGRATIONS 流程是否兼容
🔴 新增/修改 ledger tx_types 常量    → ky.py 的 UPDATE_TX_TYPES 是否需要同步
🔴 改动 Go 版本 / PG 版本 / Redis 版本 → provision.sh 头部版本注释 + 安装段
🔴 改动 Nginx 路由 / SSL / 反代规则  → provision.sh 的 nginx 配置段
🔴 改动 systemd 服务配置             → provision.sh 的 dgs.service 段
🔴 新增需要部署同步的目录            → ky.py 的 SYNC_ITEMS 列表
🔴 改动 i18n 语言列表 / 翻译流程     → ky.py 的 task_translate_locales
🟢 纯业务逻辑 / 前端 UI 改动        → 不需要动这两个文件
```

原则：**改了关键基础设施代码，必须自查 ky.py 和 provision.sh 是否需要联动**，不能只改应用层就完事。
