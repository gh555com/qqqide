# new_log/ 目录说明

## 这是什么
qqq-shell-v2 AI 面板的持久化日志目录。所有关键诊断事件写入此目录，不依赖浏览器 Console（重启即丢失）。

## 日志文件
- `agent-YYYY-MM-DD.log` — agent-loop 诊断事件（每天一个文件，自动轮转）

## 写入机制
通过 Electron IPC bridge 的 `fs.append`（真追加）写入磁盘，失败时静默降级。
每 10 秒或满 20 条自动刷盘。

## 日志开关
- 文件日志: Console 执行 `window.__qqq_file_log = false` 关闭，`true` 恢复。重启默认开启。
- 压缩埋点: `content-gateway.js` 中 `COMPACT_DEBUG` 设为 `false` 关闭完整压缩记录。重启生效。保留最近10条在 `_compactTraces` 内存中。

## 全部关键事件

### 连接超时全链路
| 日志 | 含义 |
|------|------|
| `⏰ ABORT [deadline/watchdog_stream/watchdog_output/unknown] panel=... floor=... house=... url=... retry=... abortRetries=... lineSwitches=... elapsed=...` | 超时触发点，含完整上下文 |
| `⏳ abort retry #N/3 in Xs (same URL: ...)` | 同 URL 退避重试 |
| `↳ abort recovery: line switch #N/2 OLD → NEW` | 超时后切线路 |
| `✗ TIMEOUT EXHAUSTED: ... Final URL=...` | 所有恢复耗尽 |

### 孤儿 tool_calls
| 日志 | 含义 |
|------|------|
| `repair-A: idx=... expected=... actual=... removeCount=... (floor ...)` | 方向 A 详细拆除：哪个索引、期望几个、实际几个 |
| `🔧 repaired: removed N orphaned msgs (direction A/B, floor ...)` | 每轮修复汇总 |
| `ORPHAN DETECTED at source: ...` | 工具推入时计数不匹配（根因探针，极少触发） |
| `[CRITICAL] saving corrupted conversation: repaired N ...` | 保存前发现并修复了脏数据（`_saveAgentQuestData` 触发） |
| `[CRITICAL] auto-save caught dirty conversation: repaired N ...` | 自动保存前发现并修复了脏数据（auto-save 触发） |
| `[CRITICAL] repaired past floors: N floors rewritten to sq3` | 修复后重写了受影响的过去楼层（根治，不再复活） |

### 线路切换
| 日志 | 含义 |
|------|------|
| `↳ line switch #N/2 → URL (panel=..., floor=...)` | HTTP/网络错误触发的线路切换 |
| `↳ abort recovery: line switch #N/2 OLD → NEW` | 超时触发的线路切换 |
| `HTTP/2-like error (retry N/3), skipping remaining → line switch` | HTTP/2 连接池错误提前切线路 |
| `✗ fetch exhausted: ... (consecutive=..., panel=...)` | 单条线路重试耗尽 |

### SSE 错误（2026-06-15 新增）
| 日志 | 含义 |
|------|------|
| `✗ SSE error: code=400 msg=... floor=N house=M` | 服务端 SSE 错误事件（不再被吞），含错误码和楼层位置 |
| `⚠ SSE ended with usage only, no content — upstream likely rejected request (prompt_tokens=... total_tokens=...)` | AI 返回了 usage 但没有内容（超限拒绝或异常），含精确 token 数 |
| `⚠ unexpected response type: ... _usage={prompt:..., total:..., completion:...}` | 客户端收到无 type 字段的响应，含 usage 数据用于诊断 |
| `✗ _callGateway SSE error throw: code=... msg=...` | SSE 错误在 _callGateway 层重新抛出（用于重试决策） |

### 其他
| 日志 | 含义 |
|------|------|
| `AI upstream 400/422 — skipping retries` | AI 上游错误直接走 auto-repair |

## 日志级别建议
- **开发调试**：全部开启 + `COMPACT_DEBUG = true`
- **日常使用**：保持默认（`window.__qqq_file_log = true`，`COMPACT_DEBUG = false`）
- **极致性能**：`window.__qqq_file_log = false` + `COMPACT_DEBUG = false`

## 维护
- 日志按天轮转，旧文件不自动删除，可手动清理 `agent-20*.log`
- AI 诊断问题时，先读最新日志文件末尾 200 行
- 搜索关键字 `CRITICAL` 可快速定位 conversation 腐蚀事件
- 搜索 `SSE error` 可快速定位服务端错误
