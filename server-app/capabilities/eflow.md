E-Flow v2（**可选**的项目文档地基 · 每轮被注入的那份东西）：一律用 `eflow` 工具，禁手工数数、禁手改生成区。

· 入口（只有三处，全部用户主动；禁 AI 自己推销）：① `~New quest~` 卡片「E-Flow」= 让**一切项目**接入（点一下 = 发一句话；已开时这张卡自己不出现）② 设置 → 高级 → 「E-Flow」→〔管理〕= 人自己接管/体检/整理/取消（同一条内核，不走 AI）③ 用户在对话里明确说「要接入 / 文档怎么管」→ 项目级 `eflow upgrade`。
· ★ 暗号 = 「**让一切项目接入 E-Flow**」（中文原句 `一切项目接入 E-Flow`）：用户这么说 = **全局接管**，直接 `op=global action=ask`——禁只接当前项目、禁先解释一段再说。
  ★ 暗号卡片跟界面语言走：非中文用户点卡发出来的是一句**外语**（如 en `Integrate all projects with E-Flow` / de `Alle Projekte an E-Flow anbinden`），语义**一字不差**就是这个意思——看意思，不要只认中文那六个字；品牌词 `E-Flow` 在任何语言里都不翻译，出现它 + “全部项目”就是同一件事。回不回 1 与语言无关（机器只认那一个字符）。
· ★ 全局接管 = **暗号 1**（机器判定，不许走捷径）：
  1. `eflow op=global action=ask` → 返回 data.say（固定确认语，**已按用户界面语言渲染**，末行写着「回复 1 代表确定」）+ 一次性令牌 → **把 say 一字不改地说给用户，说完就停**（禁自己补解释、禁自己翻译回去、禁自己往下做）。
  2. 用户回 **`1`** 才调 `action=on|off`，带 `token=<上一步的令牌>`。客户端只认这一个字符（全角 １ 也认）：**除 1 之外的一切回复——包括「确定」「好」「OK」「取消」、反问、换话题、沉默——一律什么都不写，而且不要再问一遍。** 令牌 30 分钟、一次一用；拒绝不烧令牌（他改口回 1 仍然认）。**禁把「嗯」当同意、禁把沉默当同意。**
     ★ 用户原话由客户端从**会话真相**里取（最新一条真实用户消息），你写的 confirm 字段没有任何作用，也禁在同一个楼层里自己补一句 1（那不算他回复）；拿不到会话时工具会拒绝，并让你引导用户去设置面板。
  3. 开着时**机器自己**会把白纸项目接进来（铺骨架 + 写一行 rule，幂等），AI 不用重复做；已经有自己规则库的项目一个字都不动，只把每轮字数报给用户。
  4. 对账：状态开着但 global.txt 里的规则块被手删了 → `action=repair` 补回（`action=status` 会报漂移）。要关：`action=ask act=off` 走同一条确认链（已接入的项目保持现状，拆单个项目用 `op=detach`）。

· ★ 白纸原则：项目默认什么都不接。**禁在用户没开口时跑 init/upgrade**（那会往人仓里写文件、改 project.txt）。项目**已经在用自己写的 rule"…" 当注入源**时，`upgrade` 在机器层面**直接拒写**（不是提示）：此时只允许 op=status / op=check 把数字报给用户；迁移只能由用户自己到 设置 → 高级 → E-Flow →〔迁移到 E-Flow（保留我的规则）〕点两下（AI 侧 force 恒为 false，你也没有这个权限）；★ **禁绕开**——不许用 write_file / edit_file / run_command 去改 project.txt 或替他「顺手迁一下」，那等于你替人重写他每轮都在吃的规则。全局接管开完也一样：只有**白纸**项目才自动接，自有知识库的项目一个字都不动。用户问「文档怎么管 / 上下文塞满」→ 先 op=status 拿数字，再问他要不要接 E-Flow；他说接才动手。反悔用 op=detach（只拆 EF2 自己那一行 rule，文件不删；purge=true 才把骨架目录改名归档）。
· 用户已经有自己的规则库（project.txt 里有自己的 rule"…"）→ 完全合法，体检只量成本不拦人；禁把他的 rule 行删掉或「归一」。只有误指到别的项目 EF2 L0 的残行会被 BLOCK。

· 任何「文档太重 / 上下文塞满 / 不知道读哪份 / 规则散落」的诉求 → 先 `eflow` op=status：它会给出每轮固定注入多少字、各层有几份文档、经验几条。先拿数字，再说结论。
· 收尾前 op=check 必须 PASS（十道闸：注入面 / 体积 / 死链死路由 / 经验 schema / 索引同步 / 腐烂 / 密钥 / 放宽可见 / 生成区同步 / 成本）。BLOCK 逐条改到消失；WARN 允许存在，但必须在回复里如实说出来。
· L0（`_qqq/alphal/expert/index.md`，≤2500 字）里的 `EF2:BEGIN … EF2:END` 那段是生成区：它由各文档头部的 `# WHEN：…` / `# MUST：…` 编译而来。要改路由表或加铁律 → 改文档头，再 op=index。禁直接改生成区（体检会 BLOCK）。
· 新项目：op=init（幂等，绝不覆盖已有文件）。老项目把一份大文档当注入源：op=upgrade 只做机械迁移（停注入、改写 project.txt、建骨架、备份），铁律归位与细则拆分是 AI 的活，做完 op=check 必须 PASS。
· 写经验（L3）：一次具体、有代价、会复现的坑 → `_qqq/alphal/expert/exp/exp-YYYYMMDD-NNNN.md`，front matter 必填 id/date/domain/state/triggers（triggers 写「用户会怎么问」的词），正文四段：现象/根因/定式/证据。单条 ≤2000 字。期满 op=rotate --apply 归档并重建 INDEX.tsv。
· 预算要放宽：写 `_qqq/alphal/expert/budget.json`（带 _reason），禁改内核里的默认值；体检会把放宽项打印出来。
